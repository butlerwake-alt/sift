# SIFT paper results

Educational paper-trading research board. Simulated $10,000 accounts only — no exchange keys, no live orders, no leverage. Not financial advice.

- `data.js` is generated by `build_data.py` from the daily paper-test records. Do not edit it by hand.
- `history.json` holds the daily marks. It is append-only: existing marks are never rewritten.
- `template.json` holds the descriptive text for each strategy (rules, hypothesis, backtest, risk, why).
- `publish.sh` rebuilds, checks that `data.js` and `research_data.js` parse and carry the required fields, and commits/pushes only if something changed.

## Required field: `why` ("Why we picked this")

Every strategy — on the paper board AND on the researched-strategies page — must carry a `why` note describing the
original backtest that led to choosing it. This is required for all strategies going forward.

- Paper board: `template.json` → each strategy needs
  `"why": {"text": "...", "records": ["path/under/workspace", ...], "hasRecord": true|false}`.
  `build_data.py` copies it from `template.json` into `data.js` on every run (also when a strategy's records are stale) and
  stops with an error if any strategy lacks it; `publish.sh` also refuses to publish without it. It shows on `strategy.html`.
- Use only figures that exist in saved records under `/workspace` and list those files in `records`. Never invent numbers.
  If no original backtest exists for the exact rules, say so plainly and set `hasRecord` to false.
- Researched strategies: `build_research.py` writes `why` from the frozen backtest results (the new backtest is the reason)
  and refuses to build if `name`, `plain`, `sources`, `rules`, `why` or `verdict` is missing.

## Researched strategies page (`research.html`)

- Historical backtests of strategies shared online and on social media. NEW EXPERIMENT dated 2026-11-10; not live signals,
  not part of the paper board.
- Descriptions, rules, source links and interpretations: `research.json`.
- Numbers come from the frozen run in `/workspace/web_strategies/run_20261110/` (code, data snapshot with hashes, results).
  A public copy of the code and results is in `research/run_20261110/`.
- `python3 build_research.py` regenerates `research_data.js`. `build_data.py` never touches these files, so the twice-daily
  publish keeps them. Re-running the backtest with new data is a NEW experiment: put it in a new dated run folder and point
  `research.json` → `run` at it; do not overwrite the 2026-11-10 run.
